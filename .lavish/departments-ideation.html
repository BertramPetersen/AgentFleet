Decisions (2026-08-21, terminal session)

D1 fleet-native compliance agents (adopt no-mistakes patterns, not its binary) · D2 handoff at PR creation: the author agent opens the PR, a compliance agent takes the review over, the author returns to the hive · D3 global preference ledger with per-project overlay entries · D4 NO Lavish embedding — the canvas is native to the Electron app: agents write HTML artifacts into a designated folder (many per agent), the canvas renders them, no external browser ever spins up · D5 superseded by D4's shape: a Canvas workspace view listing artifacts, agent/project-scoped.

Both proposals were shaped by reading the two tools already on this machine: no-mistakes (a compiled git-proxy review gate — its behavior, config, and SQLite state were inspected, plus your real usage stats) and lavish-axi (MIT-licensed Node source, fully readable). Each section says what we adopt, what we reuse literally, and what only AgentFleet can add — then asks for the decisions.

Feature 1

Compliance Department — review agents that remember how you like your code

Every PR the fleet produces is handed to compliance agents before you see it. They review against a preference ledger — a durable, evidence-backed record of how you like code written — and every review outcome updates that ledger. The fleet maximises throughput; compliance keeps the bar.

The preference ledger — memory that earns its place

Lives in the hive (compliance/preferences.jsonl + a generated PREFERENCES.md), git-tracked by the single committer, so every learned preference has an audit trail. Injected into compliance agents at spawn exactly like identity.md is today. 

{ "id": "no-doc-comments",
  "rule": "No reflexive doc comments — comments only for non-obvious WHY, invariants, workarounds",
  "rationale": "stated in global CLAUDE.md; confirmed by 3 review overrides",
  "evidence": ["PR#4 override", "PR#7 human edit a3f1c92", "global-claude-md"],
  "confidence": 0.92, "applied": 14, "overridden": 0, "scope": "global" }
learning loop 1 — explicit

Human overrides a finding

You dismiss or override a compliance finding in Needs-you → the override text becomes a preference entry (or strengthens/weakens an existing one). Nothing is learned silently — the entry cites the override.

learning loop 2 — implicit

Post-merge corrections mined

When you hand-edit agent-written code after approval, a compliance agent diffs your correction against what was approved and proposes a preference ("Bertram rewrote X as Y — candidate rule?"). Proposals land in Needs-you; only confirmed ones enter the ledger. Mirrors no-mistakes' eval miss ingestion.

forgetting — as important

Overridden rules decay

Every entry tracks applied vs overridden. A rule you keep overriding loses confidence and retires — the ledger converges on how you actually review, not on what it once guessed. Mirrors no-mistakes' relabel-on-merge.

All three keep the preference ledger and learning loops in AgentFleet; they differ in who runs the review pass.

Feature 2

Canvas — a window where agents render what you're building together

A pane where an agent's HTML mockups render live inside AgentFleet — and where your annotations flow straight back into the agent as steering. Lavish already solved the hard parts, in MIT-licensed Node source we can read and embed.

The wiring that makes it AgentFleet's

Lavish's annotation feedback is exactly the shape of our steer mechanism. An annotation on a mockup ("this table needs a project column" pinned to #fleet-table) becomes controlSteer(agentId, …) — delivered as additionalContext at the agent's next hook boundary, no keystrokes, no interrupt. The intervene rail and the canvas become two views of one loop: watch, annotate, steer, re-render.
